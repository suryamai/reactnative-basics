YumQuick – Complete Documentation &amp; Phase-wise Build Prompt Version 2.0 · React Native + Expo + TypeScript · FastAPI backend 1. Executive Summary YumQuick is a cross-platform food delivery app built with React Native, Expo Router and TypeScript. It talks to a FastAPI backend (540+ dishes, categories, authentication, orders). Version 2.0 adds strict form validation with success and error feedback, persistent and secure user sessions, fingerprint / Face ID login, a full profile and settings area, and the complete ordering flow: cart, addresses, checkout, payments, live order tracking, favorites, reviews, and notifications. 2. Authentication, Validation &amp; Session 5.1 Validation rules ( src/utils/validation.ts  + Zod schemas) Field Rule Error message Full name 2–50 chars, letters, spaces, dots only &quot;Enter a valid name (letters only, min 2 characters)&quot; Email Standard email pattern, trimmed, lowercased &quot;Enter a valid email address&quot; Mobile 10 digits (or 8–15 with country code), digits only &quot;Enter a valid mobile number&quot; Email or phone (login) Must pass either check &quot;Enter a valid email or mobile number&quot; Password Min 8 chars, 1 uppercase, 1 lowercase, 1 number, 1 special character &quot;Password must be 8+ characters with upper, lower, number and symbol&quot; Confirm password Must equal password &quot;Passwords do not match&quot; Date of birth DD/MM/YYYY, real date, age 13+, not in the future &quot;Enter a valid date of birth&quot; Terms checkbox Required on sign-up &quot;Please accept the terms to continue&quot; 5.2 Behaviour Validate on blur and again on submit; show the red message under the field and a red border (#D32F2F). Valid fields show a green tick. Disable the submit button while loading and show a spinner; prevent double submits. A password strength meter (weak / medium / strong) and a show/hide eye icon on password fields. Server errors are mapped to friendly messages: 400 invalid data, 401 &quot;Incorrect email or password&quot;, 409 &quot;Account already exists&quot;, 422 field-level errors, 429 &quot;Too many attempts, try again later&quot;, network failure &quot;No internet connection&quot; with Retry. Success feedback: a green toast (&quot;Account created successfully&quot; / &quot;Welcome back, {name}&quot;) before navigating to  /preparing  and then Home. After 5 failed logins, lock the form for 30 seconds (client side) in addition to backend rate limiting. 5.3 Storing user data Data Where Access token + refresh token expo-secure-store (encrypted) User profile (id, name, email, mobile, dob, photo URL) AsyncStorage cache + Zustand authStore, refreshed from  GET /users/me Settings (theme, language, notification toggles, biometric flag) AsyncStorage via settingsStore Cart AsyncStorage (persisted) so it survives app restarts Remember-me email AsyncStorage (never the password) Never store the plain password anywhere on the device. 5.4 Session and route guard On launch, read tokens from SecureStore. If an access token exists and is valid, go to Home (after the loader); if expired, call  /auth/refresh ; if that fails, clear the session and go to  /welcome . The API client adds  Authorization: Bearer &lt;token&gt; , and on a 401 refreshes once and retries the request. Logout calls  POST /auth/logout , clears SecureStore, AsyncStorage user data and the cart, and routes to  /login . 5.5 Forgot / reset password Email or phone → backend sends a 6-digit OTP (mock-logged in development) → OTP screen with 60-second resend timer → set new password with the same strength rules → success message and redirect to login. 6. Fingerprint / Face ID Login Hardware check:  hasHardwareAsync()  and  isEnrolledAsync() . If unavailable, hide the option and show a hint to enroll biometrics in device settings. After the first successful password login, show a prompt: &quot;Enable fingerprint login?&quot; Choosing Enable runs  authenticateAsync  once to confirm, then saves  biometricEnabled = true  and keeps the refresh token in SecureStore. On the login screen, if enabled, show a &quot;Login with fingerprint&quot; button and auto-prompt on launch. Success restores the session using the stored refresh token; failure or cancel falls back to password. Lock the app after being in the background for more than 60 seconds (configurable: immediately, 1 min, 5 min) and require biometrics to reopen. Optionally require biometrics before placing an order or changing the password. Settings → Security: toggle biometric login (requires authentication to turn on), choose the auto-lock timeout, with a fallback to the account password after 3 failed biometric attempts. Disabling biometrics, changing the password or logging out removes the stored biometric credentials. Android: add the  USE_BIOMETRIC  permission. iOS: add  NSFaceIDUsageDescription  to the Expo config. Biometrics need a development build or a device, so test on a real phone. 7. User Profile &amp; Settings Profile tab:  photo (camera or gallery with crop), name, email, mobile, and quick links to Orders, Addresses, Favorites, Payment methods, Notifications, Settings, Help and Logout. Edit profile:  full name, email, mobile, date of birth, gender (optional), photo upload; validated with the same rules; success toast on save and  PATCH /users/me . Settings: Account: edit profile, change password, delete account (with password confirmation and a warning). Security: biometric login, auto-lock timeout, logout from all devices. Preferences: theme (system, light, dark), language, currency display. Notifications: order updates, offers and promotions, email and SMS toggles. Addresses: add, edit, delete, set default (Home, Work, Other, with map pin or manual entry). Payments: saved cards (tokenized, never raw card data), UPI, cash on delivery. Support: help center, FAQ, contact us, rate the app, terms and privacy policy, app version. 8. Backend API Reference (FastAPI) Base URL comes from  src/constants/config.ts  (for example  http://192.168.1.11:8000 , Android emulator fallback  http://10.0.2.2:8000 ). Never hard-code it elsewhere. 9.1 Existing endpoints Area Endpoint Method Description Auth /auth/signup POST Register (fullName, email, password, mobile, dob) Auth /auth/login POST Login with email or phone + password Menu /menu/categories GET Category list Menu /menu/stats GET Item count and category breakdown Menu /menu GET List dishes (category, search, limit, offset) Menu /menu/{id} GET Dish details Menu /menu POST Admin: add dish Menu /menu/{id} PATCH Admin: update price or availability Menu /menu/{id} DELETE Admin: delete dish Orders /orders POST Place order Orders /orders/{id} GET Order status Orders /orders GET Order history Orders /orders/{id}/status PATCH Update status 9.2 New endpoints required for v2.0 Area Endpoint Method Description Auth /auth/refresh POST Exchange refresh token for new access token Auth /auth/logout POST Revoke refresh token Auth /auth/forgot-password POST Send OTP Auth /auth/verify-otp POST Verify OTP, return reset token Auth /auth/reset-password POST Set new password Auth /auth/change-password POST Old + new password (authenticated) User /users/me GET / PATCH / DELETE Read, update, delete profile User /users/me/avatar POST Upload profile photo User /users/me/settings GET / PATCH Notification and preference settings Address /addresses GET / POST List and add addresses Address /addresses/{id} PATCH / DELETE Edit, delete, set default Favorites /favorites GET / POST List and add favorite Favorites /favorites/{item_id} DELETE Remove favorite Cart /cart GET / POST / DELETE Optional server-side cart sync Promo /promos/validate POST Validate a promo code and return the discount Orders /orders/{id}/cancel POST Cancel an order if still cancellable Payments /payments/create POST Create payment (mock gateway first) Reviews /reviews POST / GET Submit and list reviews Notifications /notifications GET List; PATCH to mark read Devices /devices/push-token POST Register push token 9.3 Core data models User (id, full_name, email, mobile, dob, avatar_url, password_hash, role, created_at) · RefreshToken · Address · MenuItem (id, name, category, price, image, rating, prep_time, is_veg, available) · Favorite · Order (id, user_id, address_id, items, subtotal, discount, delivery_fee, tax, total, payment_method, status, created_at) · OrderItem · Review · Promo · Notification · OtpCode. 9.4 Backend security bcrypt password hashing, JWT with a short-lived access token (15–30 minutes) and a refresh token (7–30 days), role-based access (admin routes protected), rate limiting on auth routes, CORS configuration, input validation with Pydantic, and consistent error format  { &quot;detail&quot;: &quot;message&quot;, &quot;code&quot;: &quot;ERROR_CODE&quot; } . Move from SQLite to PostgreSQL with Alembic migrations for production, and serve images from cloud storage. 10. Order Flow Browse → Food details → Add to cart → Cart (promo) → Checkout (address, payment) → Place order → Success → Tracking (received → preparing → out for delivery → delivered) → Review. Order totals are calculated on the server; the app never trusts client prices. 11. Quality, Testing &amp; Performance Run  npx tsc --noEmit  and ESLint on every phase; unit-test validators and stores (Jest); component tests (React Native Testing Library); API tests with pytest. Test matrix: valid and invalid login, duplicate signup, expired token, offline mode, biometric success, failure and cancel, no biometrics enrolled, empty cart, failed payment, order cancellation. Performance: FlatList with pagination and memoized items, image caching and resizing, debounced search (300 ms), skeleton loaders, 60 FPS animations. 12.
